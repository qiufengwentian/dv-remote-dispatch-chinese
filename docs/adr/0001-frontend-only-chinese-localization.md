# 仅网页前端与文档做中文本地化，后端保持英文

本仓库是 Remote Dispatch 的中文分叉，但本地化范围只覆盖网页前端（`frontend/` 页面文案）与项目文档，C# 后端（UMM 设置界面 GUI、日志）保持英文；落地上采用源码内联直改字符串，不引入 resx/语言表资源化方案。原因是前端是用户实际接触的界面，而后端文案主要面向开发者日志与设置面板，全量汉化收益低、却扩大与上游的合并冲突面；内联直改让 diff 简单直观、可读性优先，代价是日后合并上游时字符串所在行需要人工解决冲突。译名原则（游戏特有名词优先，其余采用中国铁路标准术语）记录在根目录 `CONTEXT.md`。

## Considered Options

- **全量汉化（前端 + 后端 + 文档）**：被拒——后端文案量小、受众是开发者与高级用户，收益低；且显著扩大与上游 `domroutley/dv-remote-dispatch` 的冲突面。
- **资源化本地化（resx / 自定义语言表）**：被拒——对 netstandard2.0 + EmbeddedResource 架构是明显改造，工程量大；本仓库定位是单语言（简体中文）成品分叉，没有多语言运行时需求。

## Consequences

- 网页呈现"中文框架 + 英文数据"混合态：任务号、场站/道岔/信号 ID、玩家名、许可证名、模式值（`Manual`/`Automatic`）等由后端提供的数据保持原样。
- UMM 设置界面与 UMM 日志保持英文。
- 合并上游时，前端字符串所在行的冲突需人工解决。
- `console.*` 开发者诊断保持英文，与后端日志同规。
